> 版本：v1.0（2026-08-17）
> 适用：papers 库全部 55 篇文献精读（01 传播 7 / 02 起源 20 / 03 核合成 24 / 04 实验 4）
> 执行主体：Hermes agent。**只审查、出报告，禁止修改任何文献文件。**
> 设计依据：项目内质量门禁经验 + 外部评估框架调研（DEER / ReportBench / RAGAS / G-Eval / CEF，2026-08-17 网络调研）

## 0. 执行边界（最高优先级，违反即终止）

1. **只审不改**：禁止修改/新增/删除/重命名任何 `literature_analysis/` 与 `background/` 下的 md 文件；禁止运行任何会写文档的脚本（`--write` 类）。发现问题只记录在报告中。
2. **禁止 cleanup/切分/搬运类操作**：git 历史里已存在的真分章文件（如 strong-2007 老库分章）属受保护对象，禁止以任何形式删除或合并。
3. **禁止用"需人工确认"占位**：每条检查必须给出明确结论（通过/不通过 + 证据）。
4. **分批执行**：按域分批（建议 01 先审 7 篇试跑），每批报告完成并交付后，等待复验确认，再进入下一批。禁止一次性审完全库。
5. **阈值按标杆校准，不按最差篇放水**：标准参照标杆篇 `0008_bell-1978`（997 行 / 9 文件 / 分章与 overview 高度区分）。

## 1. 审查流程（每篇按序执行 6 步）

### 第 1 步：声明级忠实性验证（P0，最硬门禁）

外部依据：ReportBench / RAGAS 的 faithfulness 思想——**忠实性必须拆到原子声明逐条对照原文**，不能整体凭感觉打分。

- 从该篇精读文档中提取 **5–10 条关键 `[FACT]` 声明**（覆盖不同分章，优先选：定量结论、公式、数值、历史论断）
- 逐条对照 `fulltext/` 原文（或原文 PDF 相关页），标注：
  - `grounded`：声明被原文支持
  - `partial`：部分支持（数值/条件有出入）
  - `hallucinated`：原文无此内容 / 与原文矛盾
- **hallucinated / partial 必须给出证据**（引用原文页码/段落 + 精读原文摘录）
- 输出：`忠实性: grounded X/N, partial Y, hallucinated Z` + 问题明细

### 第 2 步：覆盖度（P0）

外部依据：RAGAS context_recall——**衡量"原文关键信息被精读覆盖的比例"，而不是精读写了多少**。

- 逐章对照：原文（或 fulltext）每一章/节的关键内容 → 精读是否有对应章节覆盖
- 标出：整段遗漏（原文有重要内容、精读完全没有）、浅覆盖（有提及但缺关键细节/数值）
- 输出：`覆盖度: 原文 N 章，精读覆盖 M 章，recall ≈ M/N` + 遗漏/浅覆盖清单
- 注意：fulltext 若为重 OCR，先检查是否混入邻页无关内容（历史教训：eichler-1989 开头混入 41 行蛋白质折叠论文），混入部分不计入原文

### 第 3 步：密度与深度门禁（P1）

- 运行 `check_density.py` 核对：FACT/千字 ≥ 4.0；理论类公式数 ≥ 50（OBSERVATIONAL 名单豁免）
- **实测**行数（综述 ≥ 800、研究型 ≥ 500）——不采信报告/SUMMARY 里自报的数字，用 `wc -l` 实测；发现报告数字与实测不符的，以实测为准并标注
- 计算分章与 `00_overview` 的文本相似度（须 < 10%，防脚本搬运）；**相似度算法**：去空白后取 n-gram 重叠率，或直接用现成相似度工具
- 输出：各项实测值 + 达标与否

### 第 4 步：解读批判占比抽查（P1）

- 随机抽读 **≥3 段**（建议分散在分章不同位置）
- 判定：是"原文复述/翻译"还是"有解读/批判/跨文献联系"（如：对比其他文献、指出局限、解释物理意义、提出疑问）
- 输出：每段判定 + 一句话理由；若 3 段均属复述 → 该篇判"深度不足"（即使行数/密度达标）

### 第 5 步：格式与规范性（P1）

- §0.3 章节命名为「论文结构树」（统一口径，防按"结构树"字样误报）
- `97_quality_check.md` 无占位符、无"待补"类内容
- 表格：列数一致、无孤立行（可用 audit.py 的表格检查逻辑）
- 公式：KaTeX 可渲染（无 `.katex-error`；抽看有无裸 `<` 后跟字母、控制字符、空基数上标）
- 标题/锚点无重复；frontmatter 字段合规（authors 字符串、citations 非空、status/read_date 有值）

### 第 6 步：分维度评分（汇总）

外部依据：DEER 的维度化 rubric + G-Eval 的"先 rationale 后分数"。

- 六个维度，各 1–5 分：
  1. 忠实性（声明级验证结果）
  2. 覆盖度（recall 与遗漏）
  3. 深度/解读（解读批判占比）
  4. 密度/工作量（密度门禁 + 行数实测）
  5. 结构组织（章节结构、逻辑）
  6. 规范性（格式/表格/公式/frontmatter）
- **打分规则（防 judge 偏差）**：
  - **必须"先列出依据（rationale），再给分数"**——禁止直接出分数
  - 禁止因"文档长/格式好看/语气自信"给高分（LLM judge 的冗长偏差、美化偏差、权威偏差——历史教训：行数门槛可注水、报告数字不可信）
  - 分数对齐标杆篇：先审 `0008_bell-1978` 定"5 分长什么样"，其余篇对照该基准

## 2. 报告格式（每批一篇）

- 文件名：`docs/QUALITY_AUDIT_<域>_<YYYY-MM-DD>.md`（如 `QUALITY_AUDIT_01_PROPAGATION_2026-08-18.md`）
- **头部必须有快照**：审查时的 `git rev-parse HEAD` + 时间戳（防"报告落盘即过时"——历史教训：审查-修复并行时报告快照滞后 2 次）
- 每篇一节，含：
  - 六维分数表 + 总分（rationale 简要）
  - P0 / P1 / P2 问题清单（P0=事实错误/整段遗漏，必须修；P1=深度/格式违规，应修；P2=优化建议）
  - 忠实性验证明细（声明级）
  - 覆盖度 recall 与遗漏清单
- 每批报告末尾：本批统计（各篇分数、P0/P1/P2 数量、共性问题）

## 3. 已知坑提醒（执行时对照）

1. **报告快照滞后**：若审查期间有任何修复动作（含其他 agent 的），报告落盘后即可能过时——以当前工作树实测为准，快照 SHA 保证可回溯
2. **fulltext 混入邻页**：重 OCR 的 fulltext 可能含邻页无关内容（eichler 教训），对比时剔除
3. **行数/密度可注水**：行数达标 ≠ 有深度——第 4 步抽读是必要的兜底
4. **PDF 视觉读取法**：需要从 PDF 提取内容时用 `pdftoppm` 转 PNG 后逐页读图（防 OCR 文字层错漏），不直接依赖 PDF 文字层
5. **相似度检测**：分章与 overview 相似度高 = 搬运嫌疑，查两文件开头/结论段是否雷同
6. **公式错误特征**：红色 LaTeX 源码（.katex-error）、字面 `**` 残留、`^{数字}` 空基数上标、`M(<字母)` 裸尖括号——都是渲染/源问题信号

## 4. 交付与复验流程

1. Hermes 按上述流程审查本批 → 写报告进 `docs/` → git 提交（**只提交报告文件，不 `git add -A`**，commit message 如 `docs: QUALITY_AUDIT_01 批次报告`）
2. WorkBuddy 复验：抽 2–3 篇实测（抽查声明级验证是否真实、分数是否与依据一致、报告是否含未实测的断言）
3. 复验通过 → 放行下一批；发现注水/虚报 → 打回重审该批
4. 全部批次完成后：汇总 P0 问题清单 → 单独一轮修复指令（另设 goal，不在本 goal 内修）
