> **用途**：为 papers 库的批量/机械任务生成**自包含执行指令**的统一模板。历史一次性指令（pages 补齐、fulltext 补齐、公式 LaTeX 化、子节镜像批 1/批 2 等）已完成归档至 `docs/archive/`，其通用结构与本模板一致；本模板供未来新任务直接套用。

## 2. ⚠️ 铁律（执行前必读）

- [ ] **先核实再执行**：执行前 `ls` 核实目标文件/篇目实际存在，不信任任何来源的文件名；找不到先列目录确认，不得直接跳过

- [ ] **对照原文**：修改公式/数值必须对照原文 PDF 确认正确性，格式转换不得改变任何数值/符号语义
- [ ] **只做指定改动**：不顺手改无关内容（frontmatter/YAML/其他文件）；diff 应纯净
- [ ] **YAML 卫生**：frontmatter 用 PyYAML 权威验证（`/Users/jcxs2014/.workbuddy/binaries/python/envs/default/bin/python`）；`key:` + 顶格列表合法、`key: []` + 列表非法

## 5. 提交规范

- 每篇/每项 1 个 commit（除非另有说明），commit message 格式：`<type>(papers): <描述>`
- 只 `git add` 精确文件路径，**禁用 `git add -A`**，不碰并发文件
- 提交前 `git status --short` 确认改动范围符合预期

---

## 6. 完成报告要求

执行侧完成后报告必须包含：
1. 提交清单（commit hash + 内容 + 处数/文件数）
2. **逐项对照指令清单**的覆盖声明（哪些执行/哪些跳过/为什么——不报汇总"0 残留"式断言）
3. 自检结果（对应 §4 命令输出）
4. （如适用）未使用子代理/使用子代理的说明

---

## 7. 完成标准（复验口径）

复验方按以下口径独立复算（**不直接采信执行侧汇总断言**）：

| # | 检查项 | 口径 |
|---|---|---|
| 1 | 范围覆盖 | 按指令清单逐项核对（含跳过项原因） |
| 2 | 结构完整性 | （如 frontmatter 双闭合：`head -1 == ---` 且正文前 `---` 数 ≥ 2） |
| 3 | YAML 可解析 | PyYAML `safe_load` 全过 |
| 4 | 内容守恒 | （如 FACT/数字特征双通道，见 TROUBLESHOOTING A5） |
| 5 | 格式规范 | （如公式 LaTeX、路径 A 子节、Unicode 残留 0） |
| 6 | diff 纯净 | 仅含预期改动，无行尾/换行符噪声 |
| 7 | 工作树 | 干净（仅允许声明的 untracked） |
